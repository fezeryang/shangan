## 2. 问题清单（按维度，含代码证据）

### 2.1 功能完整性

**F1｜分考点视图只覆盖图推，结构失衡（= 用户主诉 2，成立）**
图推仅占题库 21%，却拥有全站唯一的「分考点正确率」条形视图；言语（44%）与资料（35%）只有板块级汇总。言语的「细节推断」单考点 152 题 = 整个图推题库。弱项定位粒度对三科本应一致——弱科恰恰更需要定位到考点。
（背景：该视图是 graphic-lab-interactivity-plan 5.1 的验收件，当时只服务图推实验的前后对照，属过渡产物，不该是终态。）

**F2｜同页两套考点体系，互不一致**

- 区块 3 用题库原始 `subCategory`（全库 23 个不同值）；
- 区块 4 用 `knowledgeTaxonomy` 24 个知识点（命名、粒度均不同）。
不一致实例：图谱「时针旋转」节点经 `questionsForPoint` 吸收了「位置移动」8 题（关键词含'位置移动'），显示 30 题；区块 3 显示时针旋转 22 题 + 位置移动 8 题两行。同一页面对同一概念给出两套口径。
死节点：`空间折叠`（graphic）、`混合增速`、`间隔增长率`（data）在题库中匹配 0 题，永远显示"未练习"。

**F3｜知识图谱「前往专项刷题」9/24 节点跳到空列表（bug）**
`KnowledgeGraph.tsx:968` 传 `selectedNode.shortName`，而 `PracticeMode.tsx:80` 按 `q.subCategory !== selectedSubCategory` **全等**过滤。taxonomy 命名 ≠ 题库 subCategory 的节点全部断链：

| 节点 shortName | 题库实际 subCategory | 节点背后题数 | 跳转结果 |
| --- | --- | --- | --- |
| 词句指代 | 词句理解 | 33 | 空列表 |
| 基期计算 | 基期量 | 12 | 空列表 |
| 增长量秒杀 | 增长量 | 7 | 空列表 |
| 两期比重 | 比重分析 | 22 | 空列表 |
| 平均数倍数 | 平均数计算 | 11 | 空列表 |
| 图表速读 | 综合分析 | 123 | 空列表 |
| 混合增速 / 间隔增长率 / 空间折叠 | （题库无对应题） | 0 | 空列表 |

合计 208 道真题（29% 题库）经图谱不可达。

**F4｜同页统计口径打架**
重做错题（错题本重做、练习重置后再答、模考重考都走 `handleRecordAnswer`）时：`stats.totalAnswered/totalCorrect` 每次都累计（App.tsx:327-329），`answerRecords` 只留最新一次。结果：顶部「综合正确率」可与本页雷达、分板块视图、图推视图给出不同数字。错题重做是该产品设计核心路径，冲突必然高频出现。

**F5｜无历史、无趋势**
`answerRecords` 每题仅存最新记录 → 无法做任何时间趋势（近 7 天 vs 之前、正确率曲线）。graphic-lab-interactivity-plan D13 的验收方式是"上线前后同考点正确率对照"，但当前数据结构实际只能对照"最新状态"，作答时间戳也被去重覆盖（热力图的"周作息"反映的是每题最后一次作答时间，而非真实学习作息）。

**F6｜AI 变式作答对看板不可见**
`aiAnswerRecords` 独立存储、不进任何看板。用户大量使用举一反三练习时，看板系统性低估其练习量与弱项。（上轮审计修掉了"实验室作答不进数据"，此处是同类残余。）

**F7｜无空态**
0 作答新用户看到：预测分 45/100、"击败全网 43% 考生"、雷达全 0 vs 基准 80、热力图全空 + 静态"上午 10:00"建议卡。没有任何"先去刷题，看板才有意义"的引导。

### 2.2 产品交互

**I1｜全页零折叠（= 用户主诉 1）**
6 大块常开，纵向 ~3000px+；「图推·分考点」8 行常驻。无折叠、无锚点导航。知识图谱与热力图是最重的两块，却不是每次都要看的。
（顺带：区块 4/5 的头与区块 3 头部样式一致，但没有可点击折叠的暗示——统一加折叠反而顺理成章。）

**I2｜行点击跳转是好交互但可发现性弱**
分考点行点击整行跳专项练习，仅靠页脚一行 11px 小字说明；hover 只有描边变化。通用化到三科后需要更明确的手势暗示（箭头图标/行尾"去练习"）。

**I3｜图谱承担不了"比较"职责**
力导向图适合探索全景，不适合"哪科哪个考点最弱"的排序比较（节点位置随物理仿真漂移，无法逐行扫读）。F1 的正确解法是把比较职责交给列表型分考点视图，图谱保留探索/前置依赖职责——而不是给图谱加排序。

**I4｜六维雷达语义混杂**
3 个板块正确率 + 1 个进阶图推正确率（与其他维度重叠、且无言语/资料对应项，不对称）+ 1 个由均时线性映射的"答题速度"分 + 1 个改名自 hard 正确率的"抗压稳定性"。六维不是同一量纲，雷达图的形状比较因此失去意义。

**I5｜移动端**
图谱有全屏按钮（好），但拖拽/缩放在触屏上的目标尺寸未验证；热力图 24 列在窄屏横向溢出风险。本轮仅记录，不展开。

### 2.3 数据诚实（项目自身的红线）

项目在 prompt 层有明确红线："所有结论必须严格从真实作答数据推出，绝不编造数据"（prompts.ts:92），在产品层有"信息诚实"原则（graphic-lab-interactivity-plan 0.1 第 7 条）。看板现状与该红线冲突：

**H1｜预测分与"击败全网"是虚构公式**
`estimatedScore = min(100, max(45, accuracy*0.9 + min(totalAnswered,20)*0.5))`（AnalyticsView.tsx:143-148）：下限 45 → 0 作答用户显示 45 分；`击败全网 X% = min(99, score*0.95)` 纯拍脑袋换算。零数据、无对标样本，却以确定口吻展示。

**H2｜静态文案伪装 AI/算法背书**
"AI 备考提分智能建议" 3 张卡片为硬编码文案，与用户数据无关；页脚"基于上岸测评 2026 最新校招/社招岗位大纲算法模型评估"为虚构背书。而真实的 AI 学情诊断（server.ts diagnose 链路，MistakeBook 已接入）并未在看板露出——真 AI 不用，用假 AI。

**H3｜模考用时兜底污染时间分析**
ExamMode.tsx:117,128：未逐题计时的题用 `fallbackTime`（总均时）冒充 `timeSpentSec`，进入看板全部用时指标（快/慢分桶、板块均时、热力图能效分）。同项目 PracticeMode/PatternLab 均为真实测量，仅模考造假。

**H4｜雷达基准与 0 分误导**
基准 80/85 为虚构常量；未练习维度取 0 并画进雷达（脚注有说明，但图形本身读作"能力为零"）。

**H5｜热力图附属虚构**
周矩阵"能效" = acc×0.9 + 固定加成（早间+8 其余+4，StudyScheduleHeatmap.tsx:191）；"上机考位对齐策略：上午 10:00 模拟上机"为静态卡片伪装成个性化结论。

### 2.4 工程与可访问性

**E1｜AnalyticsView 无任何 useMemo**
7 个统计块各自 `answerRecords.filter(r => allQuestions.find(...))`，O(records × 727) × 每渲染重复多次。当前量级尚可，但属无谓浪费；区块 3 的 `bank.some(...)` 更是 O(records × bank × sub)。

**E2｜组件体量违背项目自身规范**
"Keep components small and focused"：KnowledgeGraph 单函数圈复杂度 148（979 行）、StudyScheduleHeatmap 86（640 行）。

**E3｜可访问性**
全库无 `aria-expanded`/折叠先例（本轮折叠需自带）；雷达图为纯 SVG 无文本替代；热力图分档依赖颜色（点击可看数值，部分补救）；图谱节点为 D3 生成，键盘不可达（记录，不在本轮范围）。

**E4｜localStorage 无上限**
answerRecords 去重后 ≤727 条可控；但趋势化（F5 修复）后若 append-only 需要上限保护。

## 3. 结论（对用户两问的直接回答）

1. **折叠：合理且应做**，且不应只做图推一块——6 大块全部套同一折叠模式，默认展开有数据的块、折叠空块（I1/F7 一并解决）。
2. **只有图推有分考点视图：不合理**，证据见 F1（21% 题库独享唯一考点级视图，言语/资料 79% 无此粒度）。正确形态是把该视图泛化为「三板块·分考点正确率」折叠面板，比较职责归列表，图谱保留探索职责（I3）。
3. 深度研究另发现 1 个功能性 bug（F3，29% 题库经图谱跳转不可达）、1 个同页数字互相矛盾的口径问题（F4）、5 处虚构数据（H1-H5）、空态缺失（F7）等，均列入计划。

### 明确不做（YAGNI 边界）

1. **不新增图表/折叠组件库**：折叠用本地 `useState` + lucide 图标；沿用现有 recharts/d3。
2. **不把知识图谱重构为表格**：图谱保留探索/依赖职责，比较职责交给阶段 1 的列表面板（I3）。
3. **AI 变式作答并入看板（F6）**：真实价值存在，但涉及 aiAnswerRecords 聚合口径，收益/成本比低于前三阶段；待阶段 3 的 attempts 模型落地后再评估。
4. **图谱键盘可达性、移动端触控细节（E3/I5）**：单独议题，不混入本次。
5. **预测分换成更复杂的校准模型**：没有对标样本数据，任何模型都是装饰；直接删（2.1）。

### 风险与缓解

1. **0.2 口径统一改变用户已见数字**（总刷题量从"次数"变"题数"）：卡片副文案注明口径（"已练习 N 题"），重置逻辑不变。
